## Symbol Payouts

`SymbolMultipliers[].Value` is indexed by match count 1..5; positions 1 and 2 are `0` for every
symbol, so **nothing pays below three of a kind**. The values are *rates*, not currency — see
"Win Formulas" for how a rate becomes money.

| Symbol | 3x | 4x | 5x | Notes |
|--------|----|----|----|-------|
| WILD! | — | — | — | Id **9**. Pays nothing itself — it SUBSTITUTES. Confirmed live: `P2-WILD!-P2-WILD!-P3` scored as four P2 (150). **Never lands on reel 1** (strip weight 0 in every list). |
| P1 (Fuel) | 10 | — | — | Id **5** `[VERIFIED]`. A **SCATTER**, not a line symbol: `Scatters: [{Symbol: P1, Occurrences: 3, Multiplier: 10}]`, and no payline entry starts with P1. Only reels **1, 3, 5** (weight 0 on 2 and 4). |
| P2 (can) | 40 | 150 | 300 | Id **6**. 4x rate **150** confirmed live. |
| P3 (Mask) | 20 | 100 | 250 | Id **7**. |
| P4 (Cog) | 15 | 75 | 200 | Id inferred `8` (unconfirmed). |
| A | 10 | 50 | 150 | Id **1**. 3x rate **10** confirmed live. |
| K | 8 | 25 | 100 | Id **4**. |
| Q | 6 | 20 | 50 | Id inferred `3` (unconfirmed). |
| J | 4 | 10 | 30 | Id **2**. 3x rate **4** and 4x rate **10** both confirmed live. |

**FreeSpin!** (Bonus, id `11`) has no `SymbolMultipliers` entry and never leads a payline. It is
handled entirely by the free-spin award table below.

Sorted by value, the hierarchy is **P2 > P3 > P4 > A > K > Q > J**, with P1 outside it as a
scatter and WILD! as a pure substitute.

## Win Formulas

Two bet concepts are distinguished throughout (Game Logic, "Explanation of terms"):

- **base bet** — "The amount used for **payout calculation**"; the base value applied to bet per
  line and the paytable.
- **bet amount** — "The amount **deducted from the player's balance**" and "**displayed to the
  player on the UI**".

In Normal Mode, `base bet = bet amount`. Under Ante Bet they diverge — see below.

| Quantity | Formula | Source |
|---|---|---|
| Bet per line | `baseStake / betLines` (= /20) `[VERIFIED]` | Server reports `betLines: 20` every round |
| Per-line win | `payoutRate × baseStake / betLines` `[VERIFIED]` | Each payline carries its own `payoutRate` |
| Round payout | `randomMultiplier × Σ payoutRate × baseStake / betLines` `[VERIFIED]` | Exact on all 5 samples |
| Scatter win | `base bet × Multiplier` | Game Rules: "Scatter winnings: base bet × Multiplier" |
| P1 (Ways) win | `Total Ways × 10 × base bet` | Features §4 |
| Bet amount (Normal Mode) | `base bet` | Game Logic |
| Bet amount (Ante Bet) | `baseStake × anteMultiplier` (= ×3) `[VERIFIED]` | Real payload: `anteMultiplier: 3`, `baseStake: 0.6`, `stake: 1.8` |

**Ante Bet does not change payouts** `[VERIFIED]`. Bet per line and every payout stay derived
from the unchanged `baseStake`; only the amount deducted and displayed is tripled. The ante
payload proves it: it deducted **1.8** but paid `150 × 0.6/20 = **4.5**`. Had the payout followed
the inflated stake it would have paid 13.5.

### Where the design doc disagrees with the export

Four conflicts, all resolved in favour of `paytable.json` (and, where a live round exists, in
favour of the server):

| Design doc says | Export / live play says |
|---|---|
| P1 pays `Total Ways x 10 x Bet base` | **Correct** — 2 ways paid `2 x 10 x 0.6 = 12`. |
| "Icon Multi P2 : 200", labelled *3 of Kind* | P2 x3 = **40**. 200 is P4's *5*-of-a-kind. The doc's number matches nothing about P2. |
| "Bet per line = base bet/5 = 1/5 = $0.2" | `/betLines` = **/20**. Its worked "$40" payout does not hold. |
| Ante "increases the bet by 1.5x" | `AnteBet.Multiplier` = **3**; a live round staked 1.8 on base 0.6. |
| Free spins: "20, 15 and 10" for 5/4/3 symbols | **12 / 15 / 20** by *reels*, then x the ways multiplier. |

Do not restore any of the left-hand column into a test.

## P1 ("Fuel") — a scatter, paid by ways

The BO export settles what the design doc muddles. P1 is configured as a **scatter**:

```jsonc
"Scatters": [ { "Symbol": "P1", "Occurrences": 3, "Multiplier": 10 } ]
```

and its reel-strip weight is **0 on reels 2 and 4** in every distribution list — so it can only
land on reels 1, 3 and 5, exactly as documented. Structurally it is confirmed a non-line symbol:
of the 7148 payline entries, **none starts with P1** (the same is true of FreeSpin!).

```
Total Ways   = (P1 on reel 1) x (P1 on reel 3) x (P1 on reel 5)
Total Payout = Total Ways x 10 x baseStake
```

The `Multiplier: 10` in the scatter config is the same 10 as `SymbolMultipliers["P1"] = [0,0,10,0,0]`
— it pays only at three occurrences, which for a symbol confined to three reels means one per reel.

Documented worked example (Features §4) — reel 1: 2 P1, reel 3: 1, reel 5: 1 →
`2 x 1 x 1 = 2 ways`, paying `2 x 10 x baseStake`.

**Verified in live play** (`p1-scatter-win-maxwin-capped.json`): P1 (id **5**) landed `[2,0,1,0,1]`
— reels 1, 3, 5 — giving `2 x 1 x 1 = 2` ways, a reported `scatterMultiplier` of **20**, and a
`rawPayout` of **12 = 2 x 10 x 0.6**. The design doc's worked example is reproduced exactly.

> **A scatter pays on the whole bet — no `/betLines`.** `20 x 0.6 = 12`, not `20 x 0.6/20 = 0.6`.
> This is the one place the design doc's arithmetic is right where its line arithmetic is wrong.
>
> The doc's Reel Glow section calling P1 "Gun (P1 icon **Scatter type**)" turns out to be right
> about the type — only the UI name ("Gun" vs "Fuel") is wrong.

## Export vs live play — the cross-check

Every rate seen in a real BET response matches the export. This is what makes
`payline_rate_matches_paytable` a genuine BO-to-balance check rather than a tautology:

| Live payline | Reported `payoutRate` | Export |
|---|---|---|
| `A-A-A-J-A` | 10 | A x3 = 10 ✓ |
| `A-A-A-FreeSpin!-A` | 10 | A x3 = 10 ✓ |
| `J-J-J-A-K` | 4 | J x3 = 4 ✓ |
| `J-J-J-J-P2` | 10 | J x4 = 10 ✓ |
| `P2-WILD!-P2-WILD!-P3` | 150 | P2 x4 = 150 ✓ (two Wilds substituting) |

The win is the **leading run**; the first non-matching, non-Wild symbol ends it. The 7148-entry
`Paylines` array in the export is just this table expanded over every wild-substitution
combination — its distinct rates are exactly the union of the `SymbolMultipliers` values.

Per-line win = `payoutRate x baseStake / betLines`; the round total is that summed across lines and
multiplied by `randomMultiplier`. Full derivation in
[../../bet-response.md](../../bet-response.md) §5.

## Special / Bonus Payouts

### Free Spin Awards `[VERIFIED]`

**The award is REEL-based, then multiplied by ways.** Both readings in the design doc are wrong,
and so is a symbol-count reading:

```
reels = number of distinct REELS holding a Bonus symbol   (>= 3 to trigger)
base  = 12 / 15 / 20   for 3 / 4 / 5 reels
ways  = product of the per-reel Bonus counts
award = base x ways
```

| Reels with a Bonus | Base free spins |
|---|---|
| 3 | 12 |
| 4 | 15 |
| 5 | 20 |

The base column is the export's `BaseGame.FreeSpins` table verbatim —
`[{Occurrences: 3, FreeSpins: 12}, {4: 15}, {5: 20}]` — where **"Occurrences" means REELS**.
Confirmed by a real payload: Bonus counts per reel `[1, 2, 0, 2, 0]` -> 3 reels, ways
`1 x 2 x 2 = 4`, base 12 -> **48 free spins**, exactly what the server awarded. Reading
"Occurrences" as symbols would give the 5-entry (20), and 20 x 4 = 80, which is not what was paid. By total symbol
count (5 Bonuses) it would have been 20; by the doc's "Base Free Spins (3 reels): 15" it would have
been 60. Full working in [../../bet-response.md](../../bet-response.md) §6.

⚠️ **The trigger is 3+ distinct REELS, not 3+ symbols.** Two Bonuses stacked on one reel plus one
on another does NOT trigger — a captured base round with Bonus on reels 1 and 4 only awarded
nothing.

**Re-trigger uses the same table** `[VERIFIED]`: `FreeSpinGame.FreeSpins` is byte-identical to
`BaseGame.FreeSpins`, so a retrigger inside the bonus awards `base(reels) x ways` on the same
terms. That closes the question the design doc left blank.

### Free Spin Multiplier

"Every free spin payout during Free Game are multiplied by the respective Freespin
Multiplier(**x1**, **x2**, **x5**, **x10**), enhancing potential rewards" (Game Rules; repeated in
Features §3, which names the mode "Bonus Game A").

### Random Multiplier — with the real weights

Ladder **x1 / x2 / x5 / x10**, and the export gives the selection weights the design doc omits.
They differ between modes, which matters when judging whether a bonus "felt" unrewarding:

| Multiplier | Base game | Free spins |
|---|---|---|
| x1 | 800 | 650 |
| x2 | 165 | 250 |
| x5 | 30 | 60 |
| x10 | **5** | **40** |

Per 1000. So x10 is 8x more likely inside the bonus, and the base game is x1 four spins in five.
Also confirmed: the multiplier applies in the **base game** too, not only in free spins as the
design doc implies — two captured base rounds carry `randomMultiplier: 2`.

None documented. No Minor/Major/Grand or progressive jackpot tier appears in the source corpus.

## Win Tier Multiplier Table

| Win Tier | Condition (Multiplier Range) |
| ----- | :---: |
| **Slim Win** | 0x < win < 1x |
| **Small Win** | 1x ≤ win < 2.5x |
| **Medium Win** | 2.5x ≤ win < 6x |
| **Big Win** | 6x ≤ win < 15x |
| **Mega Win** | 15x ≤ win < 40x |
| **Ultra Win** | win ≥ 40x |

Source: Features §8. Note the boundaries are stated as strict/non-strict exactly as reproduced
above — 1x is a Small Win, not a Slim Win.

⚠️ The doc does **not** state whether `win` is measured against **base bet** or **bet amount**,
and the captured ante round makes the ambiguity concrete: it paid 4.5, which is **7.5x** the
baseStake of 0.6 (a Big Win) but only **2.5x** the 1.8 actually staked (a Medium Win). Which one
drives the celebration is still unconfirmed. Resolve it before asserting win tiers on ante spins.

## Paytable Rules / Weights

- **Evaluation direction:** "All symbols pay from left to right on adjacent reels starting from
  the leftmost reel, except Freespin and P1 which pay for any reel" (Game Rules).
- **Wild substitution:** "The wild symbol can substitute for any symbol Except Bonus(Freespin)
  and P1, increasing chances of forming winning combinations" (Game Rules).
- **Symbol distribution lists** (Features §7) — the game samples symbols from multiple
  distribution lists rather than one fixed reel strip:

  | Mode | Rules for re-selecting the list | Description |
  | ----- | ----- | ----- |
  | **Main Game** | Threshold = 1 | Each spin → select a new list |
  | **FreeSpin** | Threshold = 1 + Every Spin Reselect | Each spin → select a new list |

  With Ante Bet active the game uses **List 3** — confirmed by the export:
  `AnteBet: {Multiplier: 3, DistributionListId: 3}` in both BaseGame and FreeSpinGame.
- **The list weights ARE in the export**, and they show what ante actually buys. List 3 loads the
  reels with Wilds:

  | | reel 1 | reel 2 | reel 3 | reel 4 | reel 5 |
  |---|---|---|---|---|---|
  | WILD! weight, normal lists (1 / 2) | 0 | 2 | 2 | 5 | 5 |
  | WILD! weight, **ante list 3** | 0 | **24** | **24** | **26** | **20** |

  A 5-10x increase on every reel that can hold one — which is precisely the documented
  "Activating the Ante-Bet will increase the chance to win raining wild feature… More Wild symbols
  are present on the reels", now quantified.
- **Wild never lands on reel 1.** Weight 0 there in every list, base and free game alike. Neither
  design doc states this; it exists only in the config.
- List selection weights: base game 47 / 48 / **5**, free game 27 / 40 / **33** — so list 3 is rare
  in normal base play but common in the bonus.
- **Raining Wild does not affect the math:** "This is a visual effect only. The animation does
  not influence or alter the mathematical outcome of the game. Win evaluation is always based
  solely on the originally generated result" (Features §1).
